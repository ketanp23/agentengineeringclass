Section 01 · Meet the tools

The three things Claude can do in this activity

Before you start, a one-screen briefing on each capability you'll use — what it is, how it changes Claude's answer, and when to reach for it. You'll see all three in action across the steps.

Claude Web Search

Live, cited facts · in the claude.ai chat

By default, Claude answers from what it learned during training, so it can't know what happened after its cutoff. Turn Web Search on (the ＋ menu in the message box) and Claude can look things up on the web mid-answer, then weave the findings in with clickable citations you can verify. It decides when to search based on your question.

Without web search"UPI processes billions of transactions a month." Fluent, but undated — could be a year old.
With web search"UPI hit a record ~20bn transactions in July 2026 [npci.org.in]." Dated, sourced, checkable.
Reach for it whenanything with a date on it — current trends, competitor moves, regulation, latest figures. In this activity: Step 2 of each engagement.

Claude Artifacts / File creation

A finished, downloadable deliverable · in the claude.ai chat

Normally Claude's reply lives as text in the chat window — you still have to copy it into Word or PowerPoint and format it. When your prompt asks for a document, one-pager, deck or spreadsheet, Claude instead builds it as an Artifact: a finished file that opens in a side panel next to the chat, with a Download button (.docx, .pptx, .xlsx, and more). Same chat, but the output is a deliverable, not just an answer.

Plain chat answerThree trends written as text — you reformat into a one-pager yourself (~30 min).
As an ArtifactA downloadable one-page .docx with title, sections and a sources footer — minutes from sendable.
Reach for it whenyou need an actual client deliverable — a one-pager, briefing note, deck or model. In this activity: Step 3 of each engagement (kept on Web Search so the file uses current data).

Claude Cowork Optional · desktop / web / mobile

An agent you delegate a whole workstream to

Chat and Artifacts answer one message at a time. Cowork is Claude's agent for knowledge work: you hand it a whole task and it plans, breaks the work into steps, and produces several finished files — working directly with a folder of your files and connected apps, and pausing to ask before anything material. You start it from the same message box: pick Cowork instead of Chat, point it at a folder, describe the outcome, and step away. Claude Chat helps you think and respond; Claude Cowork helps you delegate and produce a finished deliverable.

Chat / ArtifactsOne deliverable per prompt; you drive each step and each file yourself.
CoworkOne instruction → it reads your existing file, works across formats, and returns several files — like leaving work for a capable colleague.
Where: ＋/mode selector → choose Cowork Plans: paid (Pro, Max, Team, Enterprise) Not: free, and not unsupervised — you review its work
Reach for it whena task spans multiple files or steps built on things you already have. In this activity: the optional Step 4 of each engagement — the morning-after follow-up pack.

Section 02 · Concept

What you're testing, and how you'll judge it

This activity is a controlled experiment: one consulting task, run three ways. The same base prompt goes into plain Claude chat, then Claude with Web Search, and finally the task is upgraded to make Claude produce a real downloadable Artifact/file. Because the task never changes, any difference in the outputs comes from the tool — and you'll capture those differences in a comparison grid.

You run BOTH engagements: Engagement A (Suvarna Bank → Word one-pager) and Engagement B (Torque Capital → 5-slide deck). Each has its own complete step-by-step walkthrough below. Work through Engagement A first, then Engagement B — the second run is faster because the clicks are identical; only the prompt and the artifact change.

Step 1 · Plain chat

Claude, knowledge only

No internet, no files. Claude answers from what it learned in training. Fast and fluent — but it can't know what happened last month.

Step 2 · + Web Search

Claude, looking things up live

Same Claude, but it can now search the web mid-answer and cite where facts came from — dates, sources, clickable citations.

Step 3 · Artifact/file

Claude, producing a deliverable

Same claude.ai chat — but the prompt asks for a finished file. Claude researches, structures, and hands you a downloadable .docx or .pptx your partner could forward.

Step 4 · Cowork (optional)

Claude, running a workstream

In the Claude desktop app, Cowork works in a folder: it reads your existing file, plans multi-step work, and produces several files (.docx, .pptx, .xlsx) from one instruction.

The three judging criteria

After each step you'll score the output 1–5 on three criteria, each backed by a line of written evidence — never a bare number. Plain-language definitions first, so you know exactly what you're scoring.

R

Recency

"How fresh is this? Would it survive a well-read client fact-checking it against this week's papers?"

In plain language

Recency is simply how up-to-date the information is. Think of milk in the fridge: some facts stay good for years (what UPI is), others expire in weeks (this month's transaction volume, last week's regulator circular). A recent answer talks about what's happening now, gives dates, and reflects events after Claude's training data was collected.

Low recency"UPI processes around 8 billion transactions a month" — plausible, but an old figure with no date attached. Quote it to a board and you may be a year out of date.
High recency"UPI hit a record ~20 billion transactions in July 2026 (NPCI data, cited)" — dated, sourced, checkable.

Scoring anchors (1–5)

  • 1Undated, generic claims; likely stale; no way to check.
  • 2Mostly evergreen facts; freshest reference over a year old.
  • 3Some dated facts, but nothing from the last quarter.
  • 4Multiple facts from the last 3 months, with sources.
  • 5Reflects the last few weeks, with dates + citations you clicked and verified.
Evidence to write downThe single newest dated fact in the output, and one thing you know happened recently that the output missed.
S

Structure

"Could your partner — skimming at the airport gate — absorb this in 30 seconds?"

In plain language

Structure is how well the answer is organized — a clear skeleton versus a wall of words. Think of a well-packed suitcase versus clothes dumped in a bag: same contents, very different usability. Good structure means clear headings, a consistent pattern per section (what it is → proof → so what), the most important point first, nothing repeated.

Weak structureLong tangled paragraphs where the point, the data, and the implication are mixed together — the reader hunts for the "so what," and section 2 quietly repeats half of section 1.
Strong structureEvery section follows the identical mini-framework: bold headline → one-line definition → one data point → "So what for the client." Skim only the bold lines and you still get the story.

Scoring anchors (1–5)

  • 1Wall of text; no headings; ideas overlap.
  • 2Some ordering, but inconsistent depth and buried implications.
  • 3Clear headings; mostly parallel sections; "so what" uneven.
  • 4Fully parallel framework; skimmable; prioritized.
  • 5Consulting-grade: MECE sections, pyramid ordering, every section answers "so what" — matches the exact structure the prompt asked for.
Evidence to write downGive yourself exactly 30 seconds to skim, then look away: what did you retain? Note one structural strength and one gap.
D

Deliverable quality

"How many minutes of work stand between this output and your partner forwarding it to the client at 9:00 am?"

In plain language

Deliverable quality is how close the output is to a finished, sendable client product — not just good ideas, but ideas in the right container. Think of a chef handing you plated food versus a bag of excellent groceries: both valuable, only one goes on the table. It covers format (a real file vs chat text), polish, client-appropriate tone, completeness (title, sections, sources), and how much rework remains.

Low deliverable qualityGreat content, but it lives in a chat window: copy into Word or PowerPoint, rebuild headings, fix fonts, add a title and sources — 30–40 minutes of formatting before it's client-safe.
High deliverable qualityA downloadable file matching the brief exactly — you'd change two sentences, drop in the Altura header, and your partner hits forward at 9:00.

Scoring anchors (1–5)

  • 1Raw chat text; substantial rewriting and full reformatting needed.
  • 2Good raw material; heavy lifting (30+ min) to make it client-facing.
  • 3Well-written and correctly toned, but still copy-paste + formatting work.
  • 4Actual formatted file; minor edits (≈10 min) before sending.
  • 5Attach-and-send: polished file matching the brief, sources included, ≤5 min of tweaks.
Evidence to write downYour honest "minutes to client-ready" estimate for each step, and the specific rework items (e.g., "no sources," "needs template styling").
📏 Golden rules for a fair test: paste the base prompt verbatim in Steps 1 and 2 · start a fresh chat for every step · no follow-up prompting in Steps 1–2 (one shot each) · screenshot every final output · Step 3 uses the framework-engineered prompt shown in its step — that upgrade is deliberately part of the experiment.
